MicroVM Grader

A LeetCode-style code grader that runs untrusted Python inside throwaway AWS Lambda MicroVMs. Built for a recorded conference demo. Region ap-southeast-1.

What it does

  • You submit Python for the two-sum problem.
  • Every submission runs in its own fresh MicroVM, restored from a snapshot of the grader-image image.
  • The grader scores it (5 tests), returns a verdict and timings, and always terminates the VM.
  • Seven hostile payloads (loop, fork bomb, memory bomb, rm -rf, network exfil, answer theft, runner kill) are contained. A correct solution run before and after proves the platform is unaffected.

The key idea: two trust zones

  • Trusted: the grader (CLI or Lambda). Holds the expected answers, AWS credentials and the comparison logic.
  • Untrusted: the MicroVM. Receives only code and inputs. Has no AWS role, no answers, no network.

1. Architecture

Red arrow = the only data path into the VM. Expected answers stay in the trusted zone, so even a fully compromised runner can only lie about its own output.

Retries: RunMicrovm and the token call use exponential backoff with full jitter on ThrottlingException. The grader also retries the first POST briefly, because traffic only starts after the run hook returns.

Layers

  • MicroVM boundary: separate VM per submission, destroyed after.
  • No execution role: nothing to steal.
  • In-VM sandbox: user, network, process and memory limits.
  • Trusted comparison: answers stay outside.
  • Hostile-reply handling: size cap, zod schema, control characters stripped.
  • Cost cap: 60 s max lifetime even if the grader crashes.

Real-service findings

  • An empty egressNetworkConnectors list still attaches INTERNET_EGRESS. The first image let exfil.py reach example.com (HTTP 200). The network is therefore cut inside the VM.
  • No "no egress" managed connector name exists (every guess was rejected).
  • Lifecycle hooks are opt-in when creating the image.
  • First request after restore is slow, so the run hook warms python up.
  • The Lambda role needs lambda:PassNetworkConnector for the default connectors.
  • Base image has Node 18 / Python 3.9 only, so the runner is bundled for node18.
